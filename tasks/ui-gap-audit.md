# UI Gap Audit — Interview Prep System

Full pass over `resources/js/`. Each item has a file:line reference, a severity, and why it matters. Checkboxes so this can be worked through like a task list.

Severity: 🔴 High (breaks the task or misleads the user) · 🟡 Medium (works, but degrades the experience) · 🟢 Low (polish)

## 1. Quiz-taking flow

- [x] 🔴 **MCQ answered via free-text `<Textarea>` instead of radio/toggle options.** [answer-form.tsx:24-31](resources/js/components/quiz/answer-form.tsx#L24-L31) renders the same `Textarea` for every question type. Root cause is upstream: `questions` has no `options` column ([migration](database/migrations/2026_08_03_231140_create_questions_table.php#L17-L22), [Question::rules()](app/Models/Question.php#L52-L62)) — MCQ options are embedded as plain text inside `prompt` per [BuildsAiPrompts.php:22](app/Services/BuildsAiPrompts.php#L22) ("for mcq, include the options inline"). Fixing the UI requires a schema change (`options: string[]`) plus a `RadioGroup`/`ToggleGroup` component, not just a frontend swap. **Fixed:** added an `options` JSON column ([migration](database/migrations/2026_08_16_202854_add_options_to_questions_table.php)), threaded it through `Question::rules()`, both question controllers, the AI generation prompt, and the quiz `<QuizController>` select. `answer-form.tsx` now renders the existing (previously unused) `RadioGroup` component for mcq questions, and `manual-question-form.tsx` gained an options editor (add/remove rows, radio to mark the correct one) instead of a plain reference-answer textarea for that type.
- [x] 🔴 **Coding answer is a plain `<Textarea>`, not a code editor.** [answer-form.tsx:24-31](resources/js/components/quiz/answer-form.tsx#L24-L31) — no syntax highlighting, no line numbers, and critically no Tab-key handling: pressing Tab in a native textarea moves focus to the Submit button instead of indenting code. **Partially fixed:** Tab now inserts an indent instead of moving focus (`handleTabIndent` in [answer-form.tsx](resources/js/components/quiz/answer-form.tsx)) — the specifically-flagged critical bug. Syntax highlighting/line numbers are NOT done — no code-editor library (CodeMirror/Monaco) is installed, and adding one is a dependency decision I didn't make unprompted. Say the word and I'll add a lightweight one.
- [x] 🟡 **No sample test cases shown before submitting a coding question.** `QuizQuestion` ([interview-prep.ts:13-19](resources/js/types/interview-prep.ts#L13-L19)) never sends `test_cases` to the client, and [question-card.tsx](resources/js/components/quiz/question-card.tsx) only shows a `language` badge. The learner has no idea what input shape/stdin-stdout contract is expected until after grading fails. **Fixed:** `QuizController` now selects `test_cases` and question-card.tsx renders them via a new [SampleTestCases](resources/js/components/quiz/sample-test-cases.tsx) component. Note: the schema has no hidden-vs-sample distinction, so this shows the full test suite, not a curated subset — a bigger schema change if hiding some cases matters later.
- [x] 🟡 **No "Run" / practice execution before submitting.** Every submit is a real graded attempt via `CodeExecutionService`; there's no lower-stakes way to test code against the sample cases first. **Fixed:** new `POST questions/{question}/run` route (`QuizController::run`) executes the submission via `CodeExecutionService` and re-renders the page with a `runResult` prop — no `Attempt` row is created. `answer-form.tsx` has a "Run against sample test cases" button (coding only).
- [x] 🟡 **Reference answer for coding questions leaks execution plumbing.** [result-feedback.tsx:58](resources/js/components/quiz/result-feedback.tsx#L58) dumps the raw `reference_answer`, which is a full script with the stdin/stdout boilerplate (`JSON.parse(require('fs').readFileSync(0, 'utf8'))...`) baked in — not a clean "model solution" a learner would want to study. **Partially fixed:** added a caption clarifying it includes the auto-grading I/O wrapper, so it reads as intentional rather than sloppy. The plumbing itself is NOT stripped — doing that safely needs either a second AI-generated "clean" field or fragile string-parsing heuristics, both bigger changes than this pass.
- [x] 🟢 **Test case results are raw `JSON.stringify` dumps.** [result-feedback.tsx:43-45](resources/js/components/quiz/result-feedback.tsx#L43-L45) — no formatting/diffing for nested objects or arrays, hard to scan. **Fixed:** switched to `JSON.stringify(value, null, 2)` in a new shared [formatJson](resources/js/lib/format-json.ts) helper — nested structures now pretty-print across lines; scalars stay inline. Still no true diffing (side-by-side expected-vs-got highlighting) — flagged as a further nice-to-have, not done.
- [x] 🟢 **No visible session progress or review-queue state.** `questionNumber` is just `excludeIds.length + 1` ([use-quiz-session.ts:29](resources/js/hooks/use-quiz-session.ts#L29)) with no total; and the backend's spaced-repetition fields (`review_bucket`, `review_due_at`) are never surfaced — the learner can't see what's "due for review" vs. new. **Fixed:** `QuizController` now sends `totalQuestions` (approved count for the topic+difficulty) and a computed `review_status` (`new`/`due`/`scheduled` — translated from the raw `review_bucket`/`review_due_at` fields per the data-presentation convention, not exposed raw). `question-card.tsx` shows "Question N · M available" plus a badge for due/new questions.
- [x] 🟢 **No way to skip or go back.** Quiz flow is strictly forward, one question at a time. **Fixed:** "Skip this question" (adds the current question to `exclude` without creating an attempt) plus a "← Previous question" link, backed by a new `GET questions/{question}/back` route (`QuizController::back`) that re-shows the last-excluded question with it removed from `exclude`, so it becomes the current question again and re-excludes itself naturally once dealt with.
- [x] 🟢 **No indication of the 5s execution timeout.** `CodeExecutionService::DEFAULT_TIMEOUT_SECONDS` ([CodeExecutionService.php:13](app/Services/CodeExecutionService.php#L13)) is invisible to the user; a slow/looping solution just fails with no context. **Fixed:** the constant is now `public`, threaded through `QuizController` as `executionTimeoutSeconds`, and shown as a caption under the coding answer box.

## 2. Question authoring / management

- [x] 🔴 **Manual MCQ authoring has no options field either.** [manual-question-form.tsx](resources/js/components/questions/manual-question-form.tsx) mirrors the schema gap in §1 — confirms this needs a backend change, not just a quiz-page fix. **Fixed** — same `options` schema/UI work as the §1 item; the manual form now has an add/remove options editor with a radio to mark the correct one.
- [x] 🟡 **Coding test cases are entered as a raw JSON textarea with no structured editor.** [manual-question-form.tsx:93-104](resources/js/components/questions/manual-question-form.tsx#L93-L104) — no add/remove-row UI, and no way to verify the reference answer actually passes those test cases before saving. (The runtime check I ran manually via `CodeExecutionService` for the imported JSON files isn't exposed anywhere in the product itself — a bad reference answer can sit as an approved question and only surface when a student's correct submission gets marked wrong.) **Partially fixed:** added a "Verify reference answer against test cases" button that POSTs to a new `questions/verify` route ([QuestionController::verify](app/Http/Controllers/QuestionController.php)), runs the existing `CodeExecutionService` before saving, and renders per-case pass/fail via a new shared [TestCaseResults](resources/js/components/test-case-results.tsx) component (also now reused by the quiz result page). The raw JSON textarea for entering test cases itself is unchanged — still no add/remove-row structured editor, just verification of what's already typed.
- [x] 🟡 **Approve/Reject on drafts are instant, irreversible, no confirmation.** [draft-questions-list.tsx:8-9](resources/js/components/questions/draft-questions-list.tsx#L8-L9) — `router.delete` fires immediately on click, no "are you sure," no undo. **Fixed:** Reject (the destructive, truly irreversible one) now opens a confirm dialog via a new shared [ConfirmButton](resources/js/components/confirm-button.tsx). Approve stays instant — it's non-destructive (no data loss, just changes status) and reversible by rejecting the now-approved-adjacent question if needed.
- [x] 🟡 **No edit action for a draft question.** Before approving, there's no way to fix a typo or tweak an AI-generated prompt/answer — only accept-as-is or delete-and-regenerate. **Fixed:** new "Edit" button opens [EditDraftDialog](resources/js/components/questions/edit-draft-dialog.tsx), pre-filled from the draft, PATCHing a new `questions/{question}` route (`QuestionController::update`). Doesn't include the "verify against test cases" button from the create form — kept the edit dialog narrowly scoped to fixing fields, not re-running the full authoring flow.
- [x] 🟢 **No bulk approve/reject.** After a 15-question import, each of the 15 drafts must be approved one click at a time. **Fixed:** checkboxes per row + "select all on this page," with "Approve selected" / "Reject selected" (the latter confirm-gated) hitting new `questions/bulk/approve` and `questions/bulk` routes. Deliberately scoped to the current page's selection, not "approve everything matching the filter" — a blind bulk-approve across possibly-unseen pages felt like the wrong default for a destructive-adjacent action.
- [x] 🟢 **No filtering/search/pagination on the draft list.** As it grows this becomes a long flat scroll with no way to narrow by topic/type/difficulty. **Fixed:** topic/type/difficulty filter dropdowns (new [DraftQuestionsFilters](resources/js/components/questions/draft-questions-filters.tsx)) plus server-side pagination (10/page) via `?topic_id=&type=&difficulty=&page=`. Known rough edge: approve/reject/edit/bulk actions re-render the unfiltered first page rather than preserving the current filter/page — threading filter state through every mutation route was more plumbing than this 🟢 item justified.
- [x] 🟢 **Import form gives no template/example file, only an inline code snippet.** [import-questions-form.tsx:20-23](resources/js/components/questions/import-questions-form.tsx#L20-L23). Per-row import errors are flat strings keyed by row index only ([QuestionController.php:82](app/Http/Controllers/QuestionController.php#L82)), no per-field breakdown in the UI. **Fixed:** added a downloadable `public/templates/questions-template.json` (one example of each question type, linked from the import form) and switched per-row errors from `errors()->first()` to all messages joined, with 1-indexed row numbers. Still no rich per-field error table in the UI — the messages are just fuller strings, not structured.
- [x] 🟢 **`DIFFICULTIES = ['easy','medium','hard']` is duplicated** across [use-generate-wizard.ts](resources/js/hooks/use-generate-wizard.ts) and [use-manual-question-form.ts:5](resources/js/hooks/use-manual-question-form.ts#L5) (and again in [topic-card.tsx:8](resources/js/components/topics/topic-card.tsx#L8)) instead of one shared constant. **Fixed** — all three now import `DIFFICULTIES` from [question-labels.ts](resources/js/lib/question-labels.ts).

## 3. Data presentation — raw enum/snake_case leaking to users

- [x] 🔴 **Draft list shows the raw `type` enum instead of a label.** [draft-questions-list.tsx:23](resources/js/components/questions/draft-questions-list.tsx#L23) renders `{question.type}` directly — `short_answer` with the underscore intact — while [question-card.tsx:10-14](resources/js/components/quiz/question-card.tsx#L10-L14) already has a `TYPE_LABELS` map that fixes exactly this ("Short answer"). The two places disagree. **Fixed:** `TYPE_LABELS`, `difficultyLabel`, and `languageLabel` now live in [question-labels.ts](resources/js/lib/question-labels.ts) and are reused everywhere a type/difficulty/language is shown, including the two authoring selects.
- [x] 🟡 **Language badge shows raw lowercase value.** `{question.language}` renders "javascript"/"php" verbatim ([question-card.tsx:24](resources/js/components/quiz/question-card.tsx#L24)) instead of "JavaScript"/"PHP". **Fixed** — see above.
- [x] 🟢 **Difficulty renders as raw lowercase everywhere** (`{question.difficulty}`) — inconsistent with the Title Case used for type labels elsewhere on the same card. **Fixed** — see above.

## 4. Progress & Dashboard

- [x] 🟡 **Dashboard is still the unmodified Laravel starter-kit placeholder.** [dashboard.tsx:27-36](resources/js/pages/dashboard.tsx#L27-L36) — two of three top tiles and the whole lower panel are decorative `PlaceholderPattern` boxes with no real widgets. This is the app's first screen after login. **Fixed:** new [DashboardController](app/Http/Controllers/DashboardController.php) feeds real data — a "Review queue" tile (questions due now) and a "Draft questions" tile (pending review) replace the two placeholder boxes, and the bottom panel is a per-topic quick-practice list ([topic-quick-list.tsx](resources/js/components/dashboard/topic-quick-list.tsx)) instead of a `PlaceholderPattern`.
- [x] 🟢 **Progress page has no link back into practicing a topic**, no per-difficulty breakdown, no trend over time, and doesn't surface review-queue size. [progress/index.tsx](resources/js/pages/progress/index.tsx) / [topic-stats.tsx](resources/js/components/progress/topic-stats.tsx) show only accuracy % + streak per topic card. **Partially fixed:** each topic card now has a "Practice" link, and the page header shows overall accuracy + review-queue size. Per-difficulty breakdown and trend-over-time are NOT done — both need real data-modeling work (attempts grouped by difficulty; a time-bucketed history), left open rather than bolted on.
- [x] 🟢 **No aggregate/overall stats** across all topics — only per-topic cards. **Fixed:** added `ProgressStats::overall()` (total attempts, overall accuracy, review-due count, draft count) surfaced as summary tiles on both `/progress` and `/dashboard`, using a new shared [StatTile](resources/js/components/stat-tile.tsx) component.

[app-sidebar.tsx:33-44](resources/js/components/app-sidebar.tsx#L33-L44). **Fixed:** removed the dead links and the now-unused `NavFooter` component — this is a local single-user tool with no public repo/docs to point at, so there was nothing legitimate to replace them with.

## 6. Accessibility

- [x] 🟡 **Difficulty `<Select>` on the topic card has no associated `<Label>`.** [topic-card.tsx:20-23](resources/js/components/topics/topic-card.tsx#L20-L23) — no accessible name beyond whatever the Select trigger exposes by default. **Fixed:** added an `sr-only` `<Label>` wired to the trigger via `useId()` — no visual change, but the control now has an accessible name.
- [x] 🟡 **Quiz answer `<Textarea>` has no `<label>` element**, only a placeholder. [answer-form.tsx:24-30](resources/js/components/quiz/answer-form.tsx#L24-L30) — placeholders aren't an accessible substitute and vanish once the user types. **Fixed:** same `sr-only` `<Label>` pattern, applied to the free-text answer textarea (the MCQ radio options already had per-option `<Label>`s from the earlier options work).

## Suggested order of attack

1. §3 (data presentation) is the smallest, highest-value fix — reuse `TYPE_LABELS` everywhere, add a difficulty/language label map. No schema changes.
2. §1's MCQ radio UI and coding editor are the two changes you called out — but both need the `options` schema addition first (MCQ) or a lightweight code-editor component (coding, e.g. CodeMirror/Monaco already-lightweight variant — check before adding a new dependency per repo convention).
3. §2's "verify reference answer against test cases before saving" closes the loop on the runtime-verification workflow you already have in `CodeExecutionService` but don't expose in the authoring UI.
4. §4 dashboard placeholder and §5 nav cleanup are cosmetic but cheap.
